\section*{Abstract}
%==============================================================================

Large language model coding agents can execute multi-step bioinformatics analyses from a natural-language specification, writing and running the underlying code themselves. This changes what must be archived for an analysis to be reproducible: the specification, in addition to the code, becomes a primary archived artifact. In this chapter we describe a workflow in which a coding agent executes a single-cell gene regulatory network analysis end to end, directed by a single versioned prompt file. The major steps are: (1) assemble the expression data and a transcription factor list in the same gene identifier namespace; (2) write a prompt file specifying inputs, fixed parameters, expected intermediate values, and required outputs; (3) direct the agent to export the expression matrix, filter nuclei, and infer co-expression networks with GRNBoost2 on a high-performance computing cluster; and (4) select regulators and generate figures. We demonstrate the workflow on published single-nucleus RNA-seq data from sorghum root, inferring networks for three cell types from 14,792 nuclei and 1,022 expressed transcription factors. We report the agent's behavior in detail, including the environment and dependency failures it diagnosed. The protocol applies to other species and datasets, and the Notes address failure modes specific to agent-directed analysis.

\vspace{0.6em}
\textbf{Key words} Gene regulatory network, Single-cell RNA sequencing, Large language model, Coding agent, Reproducibility, Transcription factor, Co-expression network, Sorghum, Workflow automation

\section{Introduction}
%==============================================================================

Single-cell and single-nucleus RNA sequencing are now routinely applied in plant biology to study development and stress response across an increasing number of species \cite{ryu2019,denyer2019,dorrity2021,shahan2022,marand2021}. A common downstream objective is to infer gene regulatory networks (GRNs): sets of relationships linking transcription factors (TFs) to the genes they may regulate. Several computational strategies exist, including approaches based on motif enrichment in promoter regions \cite{kulkarni2018,grant2011}, machine learning on sequence features \cite{song2020}, and regression-based inference from expression data alone \cite{moerman2019,vandesande2020,aibar2017}. Our group published a chapter in this series describing a pipeline integrating scRNA-seq and scATAC-seq data with motif analysis and machine learning for GRN construction in Arabidopsis \cite{chau2023}.

These pipelines share a practical characteristic. They consist of many small steps, each requiring correct file formats, matched gene identifier namespaces, and compatible software versions. In our experience the majority of effort in executing such a pipeline is spent not on the analysis itself but on reconciling these details. This effort is rarely documented and is consequently repeated by each new user.

Large language model coding agents offer a different way of organizing this work. An agent is given a task description in natural language and then writes, executes, and debugs code to accomplish it, iterating when a step fails. The analyst specifies \textit{what} must be produced; the agent determines \textit{how}.

This shifts what should be archived. In a conventional pipeline the scripts are the reproducible artifact. In an agent-directed pipeline the agent may write different code on different runs, so the scripts are an output rather than an input. What persists across runs is the specification. We therefore treat a single versioned prompt file as the primary artifact of the analysis, accompanied by a pinned software environment and a run log recording every deviation \seenote{1}. The code the agent generates is not discarded. It is archived alongside the prompt, and should be written to the same reporting standards expected of any analysis code, so that a reader can inspect exactly what was executed.

We state at the outset what this protocol does and does not establish. The networks produced are co-expression associations inferred by GRNBoost2 \cite{moerman2019} from expression data alone. They are not validated regulatory relationships: no transcription factor binding site information is used to prune edges, and no experimental validation is performed. Edges should be read as hypotheses for further testing \seenotes{2 and 3}.

As a worked example we use published single-nucleus RNA-seq data from sorghum (\textit{Sorghum bicolor}) root \cite{baumgart2025}. This dataset was selected because it is public, annotated with 27 cell type labels, and processed to a stage requiring no reclustering. The biology of sorghum root is not the subject of this chapter; the dataset demonstrates the workflow, and the protocol applies with small modifications --- principally the species, the input file names, and the expected values recorded in the prompt --- to other species and tissues for which an expression matrix and a transcription factor list are available. The overall workflow is shown in Fig.~\ref{fig:workflow}.

\subsection{Project structure}

The analysis used a fixed directory layout separating read-only inputs from generated outputs, so that individual stages can be re-run independently. The project root and \texttt{data/raw/} were created by the analyst, and the three input files placed there manually, before the agent was invoked. The prompt file describes the remainder of the layout but does not instruct the agent to construct it; the agent created \texttt{scripts/}, \texttt{data/processed/}, \texttt{results/}, \texttt{figures/}, and \texttt{logs/} as each was first required. \section{Methods}
%==============================================================================

\subsection{Overview}

The workflow comprises four stages: preparing inputs (\textbf{Subheadings~3.2--3.5}), exporting and filtering the expression matrix (\textbf{Subheading~3.6}), inferring networks (\textbf{Subheading~3.8}), and selecting regulators and generating figures (\textbf{Subheadings~3.9--3.10}). \textbf{Subheadings~3.2--3.5} are performed by the analyst before the agent is invoked; \textbf{Subheading~3.6} onward is executed by the agent from the prompt file.

Two conventions apply throughout \textbf{Subheadings~3.6--3.10}. First, the numbered items state what the prompt file specifies and what the agent consequently does; they are not commands typed at a terminal, and the reader's role at these stages is to invoke the agent and to check the values it reports. Second, all counts given in these subheadings are the values obtained for this dataset. They are properties of the data, not parameters of the method: a reader applying the protocol to a different dataset must derive their own by inspecting the object before writing the prompt \seesub{3.3}, and write those into the prompt in place of ours \seenote{18}.

\subsection{Constructing a transcription factor list in the correct namespace}

GRNBoost2 requires a list of candidate regulators. For most species this can be downloaded directly from PlantTFDB \cite{tian2020,jin2017}. Here a direct download was not usable, and the reason generalizes to any dataset aligned to a non-reference assembly \seenote{14}.

\begin{enumerate}[leftmargin=*]
\item Determine the genome assembly used to produce the expression matrix. Here the gene identifiers were of the form \texttt{SbiRTX430.01G002500}, corresponding to the RTx430 v2.1 assembly.

\item Compare this with the namespace of the available transcription factor list. The PlantTFDB \textit{Sorghum bicolor} list uses \texttt{Sobic.*} identifiers from the BTx623 v3.1 assembly. Intersecting the two gives zero matches.

\item Do not assume that structurally similar identifiers can be converted by string transformation. Testing a naive transform against 48 known identifier pairs --- available because the marker table in ref.~\cite{baumgart2025} reports both namespaces --- produced one match, consistent with coincidence. For example, \texttt{SbiRTX430.01G002500} is not the same gene as \texttt{Sobic.01G002500} \seenote{14}.

\item Determine whether a cross-reference between the assemblies already exists. The orthology tables distributed with ref.~\cite{baumgart2025} contain only RTx430 identifiers and are therefore unusable for translating BTx623 gene annotations to the RTx430 genome.

\item Generate the transcription factor list directly in the required namespace. Submit the primary-transcript proteome for the assembly used by the expression data to the PlantTFDB prediction server (\url{https://planttfdb.gao-lab.org/prediction.php}), which applies the same family assignment rules used to build the database. Save the returned list immediately; results are held in a temporary session directory.

\item Strip transcript suffixes to obtain gene-level identifiers. For a primary-transcript proteome all entries carry the \texttt{.1.p} suffix and stripping yields a one-to-one mapping with no duplicates.
\end{enumerate}

In this example the procedure returned 1,827 transcription factors across 56 families. As a check, the family composition was compared with the precomputed BTx623 list \seenote{15}.

\subsection{Inspecting the object to establish expected values}

The expected values written into the prompt are measured from the data before the agent is invoked. They are not chosen, and they are not carried over from this chapter: with the single exception of the detection threshold, every count below is a property of the dataset in hand. Perform this inspection first and record the results \seenote{18}.

\begin{enumerate}[leftmargin=*]
\item Load the expression object read-only and report the assays it contains, which assay is set as the default, and the dimensions of each. An object whose default assay is not the one intended for inference is a common and silent source of error.

\item Identify the metadata column holding cell type labels and print the number of nuclei in each type. Where more than one annotation column is present, confirm which the original authors intended for the tissue in question \seenote{13}.

\item Identify the column recording doublet status, and count the nuclei that will remain after filtering to singlets.

\item Intersect the transcription factor list with the gene names in the matrix, and report how many transcription factors survive at several candidate detection thresholds. Choose the threshold at this point; it is the one genuine parameter in this step.

\item Record all of the above. These become the expected intermediate values written into the prompt \seesub{3.4} and the checkpoints against which the agent's reports are compared.
\end{enumerate}

In this example the inspection returned 19,316 nuclei of which 14,792 were singlets, an \texttt{RNA} assay of 25,464 features against an \texttt{SCT} default assay of 23,974, and 27 cell type labels in the \texttt{celltype} column. Of the 1,827 annotated transcription factors, 1,370 were present in the matrix, and 1,205, 1,022, and 898 survived detection in at least 10, 50, and 100 singlet nuclei respectively. A threshold of 50 was adopted, giving 1,022 regulators.

\subsection{Writing the prompt file}

The prompt file is the reproducible artifact of the analysis and should be written before the agent is invoked. We found the following elements necessary.

\begin{enumerate}[leftmargin=*]
\item \textbf{Role and constraints.} State that the agent must write numbered scripts, checkpoint every stage to disk, and never modify files in the read-only input directory.

\item \textbf{Cluster policy.} State explicitly that computationally expensive steps must be submitted through the scheduler and never run on a login node \seenote{5}.

\item \textbf{Environment.} Name the conda environment explicitly and instruct the agent not to install packages without reporting first. An agent that silently installs dependencies produces an environment that cannot be reproduced from the exported specification.

\item \textbf{Inputs.} List each input file with its expected dimensions and identifier format.

\item \textbf{Fixed parameters.} Specify every analytical choice: the metadata column holding cell type labels, the nucleus filtering criterion, the assay and data layer, the detection threshold for regulators, the target cell types, and the random seed.

\item \textbf{Expected intermediate values.} State the number of nuclei expected after filtering and the number of regulators expected to survive detection filtering. This is the single most useful element of the prompt: it converts silent errors into transparent logs that the user can examine and confirm \seenotes{12 and 18}.

\item \textbf{Known dependency issues.} Where a required fix is already known, state it. The three constraints in \textbf{Notes~8--10} were included in the prompt and applied without rediscovery.

\item \textbf{Stop conditions.} Instruct the agent to stop and report rather than proceed when an observed count differs from the stated expectation, and to fail loudly rather than substitute defaults.
\end{enumerate}

The prompt is invoked by directing the agent to read it, rather than by pasting its contents into the terminal:

\begin{lstlisting}
Read prompt.md and execute it. Start with Step 00 and stop after
Step 01 so I can check the intermediate outputs before the
inference run.
\end{lstlisting}

Stopping the agent at a checkpoint before the computationally expensive step allows intermediate values to be verified easily.

\subsection{Environment reconnaissance and construction}

Before writing pipeline code, direct the agent to report the available modules, whether Seurat 5 is provided by a module or must be installed to a personal library, the available scheduler partitions and their limits, disk quotas, and whether compute nodes have outbound network access. These findings determine the scheduler resource request and the export route, and cannot be assumed. Then build and export the environment as in \textbf{Subheading~2.4}, and verify it with the synthetic test \seenote{11}.

\subsection{Exporting and filtering the expression matrix}

This stage and those that follow are executed by the agent from the prompt file. The numbered items below state what the prompt specifies and what the agent does in response; the values reported are those obtained for this dataset and are the checkpoints against which the agent's output is confirmed.

\begin{enumerate}[leftmargin=*]
\item Load the Seurat object and identify the metadata column recording doublet status. Rather than assuming a column name, scan the metadata for a column containing the value \texttt{Singlet}; here exactly one column matched.

\item Subset to singlet nuclei. Doublets create apparent co-expression between genes belonging to different cell types, which is precisely the artifact that regression-based inference interprets as a regulatory relationship. In this example filtering reduced 19,316 nuclei to 14,792 (76.6\% retained). Per-cell-type counts are given in Table~\ref{tab:celltypes}; retention is not uniform across cell types \seenote{19}.

\item Extract raw counts from the \texttt{RNA} assay explicitly. Do not use SCT residuals \seenote{12}.

\item Convert to AnnData format. Where SeuratDisk is available, \texttt{SaveH5Seurat} followed by \texttt{Convert} is the direct route. Where it is not, write the counts matrix in MatrixMarket format together with cell metadata, gene names, and the UMAP embedding from R, and assemble the \texttt{.h5ad} object in Python \seenote{7}.

\item Verify the exported file by reading it back. Confirm the matrix orientation is cells $\times$ genes, that values are raw integer counts, that the UMAP embedding is present, and that per-cell-type counts are unchanged. In this example the exported object was $14{,}792 \times 25{,}464$ with a maximum count of 525.
\end{enumerate}

\subsection{Preparing the regulator set}

Load the transcription factor list, strip transcript suffixes, restrict to genes present in the expression matrix, and apply the detection threshold fixed in \textbf{Subheading~3.3}. In this example, of 1,827 transcription factors, 1,370 were present in the RNA assay and 1,022 were detected in at least 50 singlet nuclei, spanning 54 families. This is the regulator set used for inference. Transcription factors absent from the matrix were enriched for families with organ-restricted expression \seenote{20}.

\subsection{Network inference}

This is the computationally expensive stage and the only one requiring a batch submission. The numbered items state what the prompt specifies for each target cell type.

\begin{enumerate}[leftmargin=*]
\item For each target cell type, subset the expression matrix to that cell type's nuclei.

\item Configure parallel execution explicitly rather than accepting library defaults. Cap the thread pools used by the numerical libraries before importing them, and construct the dask \cite{dask2016} cluster with a stated number of workers and one thread per worker \seenote{10}:

\needspace{5\baselineskip}

\begin{lstlisting}[language=Python]
import os
os.environ["OMP_NUM_THREADS"] = "1"
os.environ["MKL_NUM_THREADS"] = "1"
os.environ["OPENBLAS_NUM_THREADS"] = "1"

import dask
dask.config.set({"dataframe.query-planning": False})
\end{lstlisting}

\item Run GRNBoost2 with the regulator list as candidate transcription factors and all genes as candidate targets, with the random seed fixed at 42.

\item Submit each cell type as a separate batch job so that a failure in one does not lose the others. Each job requested one node, 64 cores, 64~GB of memory, and 64 dask workers with one thread each.

\item Write the resulting edge table for each cell type with columns for transcription factor, target, and importance.
\end{enumerate}

Runtimes, memory use, and edge counts are given in Table~\ref{tab:runs}. All three jobs completed in under seven minutes with peak memory below 16~GB. Runtime did not scale with nuclei count at this range \seenote{21}.

\subsection{Selecting transcription factors for visualization}

Unlike the preceding stages, no expected values were stated in the prompt for this step, because the selection depends on the inferred networks and cannot be known in advance. The numbered items state the selection rule the prompt specifies.

\begin{enumerate}[leftmargin=*]
\item Identify marker genes for each cell type by Wilcoxon rank-sum differential expression \cite{wolf2018} against all other cell types, computed on a normalized and log-transformed copy of the matrix while leaving the stored raw counts unmodified. Retain the top 50 markers per cell type by ascending adjusted \textit{p}-value.

\item For each transcription factor, sum its GRNBoost2 importance across all edges directed at those marker genes.

\item Rank transcription factors by summed importance and retain the top ten per cell type.
\end{enumerate}

This criterion is automatic and requires no manual curation, which suits an agent-directed workflow. The selected transcription factors are listed in Table~\ref{tab:tfs}. Summed importance is a valid ranking statistic within a fixed target set but is not an absolute score \seenote{2}. A substantial minority of edges in each full network carry exactly tied importance values; these arise from a property of sparse count matrices and do not affect the selection made here \seenote{22}.

\subsection{Figures}

The prompt specifies four figures, generated by the agent at the end of the run at 300~dpi:

\begin{enumerate}[leftmargin=*]
\item A UMAP embedding coloured by cell type, using coordinates from the published object (Fig.~\ref{fig:umap}).
\item Feature plots showing expression of the selected transcription factors on the same embedding (Fig.~\ref{fig:features}).
\item A dot plot of literature-curated root marker genes across all 27 cell types (Fig.~\ref{fig:dotplot}). Of the 50 rows in the source table, 46 unique genes were plotted \seenote{23}.
\item Bipartite network plots for each target cell type, showing the ten selected transcription factors and their five highest-weighted marker targets, with edge width scaled by importance and transcription factor nodes coloured by family (Fig.~\ref{fig:networks}). Edges whose target is itself a selected transcription factor are drawn in a distinct style \seenote{3}.
\end{enumerate}

Figures~\ref{fig:umap} and \ref{fig:dotplot} reproduce features of the published atlas \cite{baumgart2025} and confirm that the exported matrix and labels are faithful to the source. Figures~\ref{fig:features} and \ref{fig:networks} present output not reported in the original publication.

\section{Notes}
%==============================================================================

\begin{enumerate}[leftmargin=*]

%--- Environment ---

\item \textbf{The prompt file must be revised as the run proceeds.} Several parameters were absent from the initial prompt because their necessity emerged only during execution --- the dask configuration, the thread caps, the AnnData assembly fallback, and the scheduler resource request. If these are recorded only in the generated scripts, the prompt ceases to be a sufficient artifact. We updated \texttt{prompt.md} at each such point and treated divergence between the prompt and the executed scripts as a defect requiring correction.

\item \textbf{GRNBoost2 importance is not an absolute or probabilistic score.} Reading the arboreto 0.1.6 source, \texttt{grnboost2()} fits one \texttt{GradientBoostingRegressor} per target gene with \texttt{subsample=0.9}, which enables an out-of-bag early-stopping heuristic with a 25-round trailing window. Each reported importance is scikit-learn's \texttt{feature\_importances\_} --- normalized to sum to 1.0 across all 1,022 predictors, \textit{separately for each target's own model} --- multiplied by the number of boosting rounds actually used. We confirmed this empirically: per-target importance totals are near-exact integers ranging from 25 to 63 (median 27), with the lower bound equal to the early-stopping window length. Consequently, summed importance ranks transcription factors validly within a fixed target set, as used here, but magnitudes are not comparable across different marker sets or cell types, because each target's contribution is rescaled by its own convergence depth. We suggest stating this explicitly wherever importance values are reported.

\item \textbf{Co-expression inference cannot distinguish direction or causality.} In all three cell types, at least one selected transcription factor had among its highest-weighted targets a gene that was itself a selected transcription factor for the same cell type. In mature-endodermis the relationship is reciprocal: \texttt{SbiRTX430.09G017700} $\rightarrow$ \texttt{SbiRTX430.09G017600} at importance 5.41, and the reverse at 4.59, between two MYB genes co-expressed at $r = 0.56$ across 282 nuclei. Their locus identifiers differ by 100 on chromosome 9, consistent with adjacent genes under this annotation's numbering convention, although we did not confirm this against genome coordinates. Two co-expressed paralogs each predicting the other equally well is the expected behaviour of a method operating on expression correlation alone. We retained these edges in the figures and marked them, as they illustrate the limitation more concretely than a general statement.

\item \textbf{Agent-directed pipelines are not deterministic in the way script-based pipelines are.} The same prompt may produce different code on different runs, and GRNBoost2 is itself stochastic and requires an explicit seed. Reproducibility therefore rests on the prompt, the pinned environment, and the fixed seed together, and the prompt must specify outputs precisely enough that different implementations produce equivalent results. We regard this as the principal limitation of the approach.

\item \textbf{Direct the agent explicitly not to run computation on login nodes.} An agent given a task on a cluster will otherwise execute it wherever it currently is. Stating the constraint in the prompt, and requiring a batch submission script as an output, produces a scheduler script that is itself a better reproducibility artifact than an interactive session.

\item \textbf{Consider the platform before beginning.} We developed this pipeline on a Windows workstation and encountered three platform-specific obstacles before any analysis ran: a malformed certificate in the Windows certificate store prevented import of dask's scheduler through a Windows-only defect in the Python standard library's \texttt{ssl} module; the thread oversubscription in \textbf{Note~10}; and an unattributable system reboot that terminated a multi-hour run. Migrating to a Linux cluster eliminated the first, made the second straightforward to configure, and removed the third. On the cluster the complete inference for all three cell types finished in under twenty minutes. Readers with access to institutional computing should use it from the outset.

\item \textbf{SeuratDisk may be unavailable, and a two-step export is a reliable alternative.} Where \texttt{SaveH5Seurat} cannot be used, writing the counts matrix in MatrixMarket format together with metadata, gene names, and the embedding, then assembling the AnnData object in Python, is transparent and avoids depending on a package with known Seurat~5 compatibility issues. Always verify the result by reading it back and confirming orientation, value type, and per-group counts. A transposed matrix produces no error and fails only much later.

%--- Data handling ---

\item \textbf{pySCENIC 0.12.1 requires setuptools below version 81.} Later setuptools releases remove \texttt{pkg\_resources}, on which \texttt{ctxcore} depends. This surfaces as an import error whose wording does not indicate the actual cause. Pin \texttt{setuptools<81} when creating the environment.

\item \textbf{arboreto 0.1.6 is incompatible with recent dask releases.} Its \texttt{create\_graph()} function calls \texttt{from\_delayed()} on an always-empty list when \texttt{include\_meta=False}, which is the only mode reachable through the public \texttt{grnboost2()} interface. Older dask versions tolerated this; the dask-expr query-planning backend raises \texttt{TypeError: Must supply at least one delayed object}. Disabling query planning before importing arboreto restores the previous behaviour. We confirmed the failure is independent of input data using a synthetic $50 \times 20$ matrix. Testing a library against trivial synthetic input is an efficient way to separate a library defect from a data problem, and is a step an agent performs readily.

\item \textbf{Cap numerical library thread pools before configuring parallel execution.} With default settings on a 12-core workstation, dask created four worker processes and each worker's gradient-boosting fits independently attempted to use the full core count through OpenMP and BLAS thread pools. The resulting contention caused workers to miss scheduler heartbeats, enter restart loops, and fail the entire run after 8~h 16~min with no output. Setting \texttt{OMP\_NUM\_THREADS}, \texttt{MKL\_NUM\_THREADS}, and \texttt{OPENBLAS\_NUM\_THREADS} to 1 and constructing the cluster explicitly resolves this. The symptom --- a long-running job producing no error until it fails completely --- is easily mistaken for a data problem.

\item \textbf{Verify the environment on synthetic data before running on real data.} A GRNBoost2 run on 50 cells, 20 genes, and 5 transcription factors should return exactly 95 edges ($5 \times 19$ non-self pairs). This takes seconds and confirms that all three constraints above are correctly applied. Two of the three failures described in \textbf{Notes~8 and 9} were caught this way rather than after hours of computation.

\item \textbf{Check which assay a Seurat object reports by default.} The default assay of the published object is \texttt{SCT}. Calling \texttt{nrow()} on the object therefore returns 23,974 features rather than the 25,464 in the \texttt{RNA} assay used for inference. The agent initially reported the SCT figure, detected the discrepancy against the value stated in the prompt, and corrected it. Without a stated expectation the wrong feature count would have propagated into the results without producing any error.

\item \textbf{Inspect all cell type annotation columns before choosing one.} This object contains a second annotation column, \texttt{cluster\_label.long}, carrying labels transferred from a leaf reference (including mesophyll and guard cell) together with several thousand missing values. It is inappropriate for a root dataset. Where more than one annotation column exists, confirm which the authors intended for the tissue in question.

%--- Interpreting the output ---

\item \textbf{Gene identifier namespaces must be validated empirically, not inferred from format.} The RTx430 and BTx623 sorghum identifiers are structurally parallel --- for example \texttt{Sobic.004G266200} and \texttt{SbiRTX430.04G278400} --- which invites the assumption that one can be converted to the other by string manipulation. Testing that assumption against 48 known pairs produced a single match. Chromosome assignment corresponds between the assemblies but gene numbering does not, and the offset is neither constant nor monotonic. Where a resource reports identifiers in two namespaces, use those pairs as ground truth before adopting any conversion.

\item \textbf{Where no cross-reference exists, annotate directly rather than converting.} Submitting the proteome of the assembly actually used by the expression data to the PlantTFDB prediction server returns assignments natively in the required namespace and applies the same family assignment rules as the precomputed lists. We first pursued an alternative route, transferring transcription factor identity from Arabidopsis through orthogroups, which recovered only 939 regulators --- roughly half --- and systematically under-recovered lineage-expanded families such as FAR1 and B3. As a check on the direct annotation, family composition agreed closely with the precomputed BTx623 list (bHLH 168 versus 174; ERF 147 versus 150; MYB 130 versus 130; bZIP 97 versus 97), which is the expected outcome for two independent annotations of two assemblies of the same species. Note also that PlantTFDB returns prediction results to a temporary session directory; save the output immediately and record the job identifier and date.

%--- Agent-specific ---

\item \textbf{Use resumable downloads for large files.} Transfers of the 1.22~GB expression object failed repeatedly with \texttt{curl: (56) schannel: server closed abruptly}. Adding \texttt{-C "-"} and retry options allows an interrupted transfer to resume rather than restart. Verify the byte count after download; a truncated file appears normal until R fails to parse it. Storing the project inside a synchronized cloud folder is an additional source of interruption for files of this size.

%--- Platform ---

\item \textbf{Maintain a run log and require the agent to update it.} We maintained \texttt{logs/run\_log.md} recording package versions, parameters, scheduler job identifiers, runtimes, checkpoint dimensions, and each deviation with its justification. Most items in this section derive from that log. An agent will maintain such a log if instructed to; it will not do so unprompted.

\item \textbf{State expected intermediate values in the prompt.} The most useful lines in our prompt specified that singlet filtering should yield 14,792 nuclei and that 1,022 regulators should survive detection filtering. Every checkpoint matched on the cluster run, which gave immediate confidence that the migrated pipeline was faithful. Where a count did not match, the agent stopped and reported rather than proceeding \seenote{12}. Without stated expectations, an agent has no basis for distinguishing a plausible-looking wrong number from a right one, and will proceed either way. The counts themselves are properties of this dataset, not parameters of the method. A reader applying this protocol must derive their own by inspecting the object before writing the prompt \seesub{3.3}. What transfers between datasets is not the numbers but the requirement that expected values be stated at all.

%--- Biological / analytical ---

\item \textbf{Doublet filtering affects cell types unequally.} Overall retention was 76.6\%, but the three target cell types differed: exodermis 85\% (315 of 371), dividing cells 84\% (801 of 950), and mature-endodermis 65\% (282 of 434). The endodermis is spatially adjacent to the abundant cortex population, which plausibly explains its elevated doublet rate. Where a target cell type loses substantially more nuclei than the dataset average, the resulting network rests on a correspondingly smaller sample.

\item \textbf{Transcription factors absent from the expression matrix are informative.} Of 1,827 annotated transcription factors, 457 were absent from the RNA assay, enriched for M-type MADS, WOX, and MIKC MADS families --- associated with floral organ identity and meristem maintenance, and not expected in three-day-old seedling root. This pattern is a useful check that the annotation behaves sensibly.

\item \textbf{Runtime is dominated by the regulator $\times$ target grid, not by cell count.} At this scale the three inference jobs took 382, 291, and 355 seconds for 282, 801, and 315 nuclei respectively; the largest cell type ran fastest. Cost is governed by the fixed $1{,}022 \times 25{,}464$ regression grid and scheduling overhead. Sizing a scheduler request from cell count alone will over-request substantially.

\item \textbf{Exact ties in importance values arise from identical target expression vectors.} Between 5.2\% and 13.2\% of edges in each network share a bit-for-bit identical importance value with two or more other edges from the same transcription factor. Inspecting one 19-way tie block, all 19 target genes were detected in exactly one nucleus --- the same nucleus --- with a count of 1 and zeros elsewhere, making their expression vectors byte-for-byte identical. Identical inputs to independent deterministic fits necessarily produce identical outputs. Below a certain detection rate, sparse expression vectors collapse into a small number of distinct patterns, and any targets sharing a pattern must tie. This is a property of sparse count matrices rather than of the inference method. It did not affect the reported rankings: no top-ranked transcription factor derived any importance from tie-block edges, because the top-50 differentially expressed markers are by construction the most robustly expressed genes and structurally avoid the regime where ties occur.

\item \textbf{Expect some published marker genes to be absent from a processed object.} Of the 50 rows in the marker table, one was an exact duplicate and three genes (\texttt{SbiRTX430.10G175100}, \texttt{SbiRTX430.08G154200}, \texttt{SbiRTX430.06G155500}) were absent from both the RNA and SCT assays of the source object, leaving 46 plotted. We verified their absence against the original object rather than the exported matrix, confirming this was not introduced by the export. Likely explanations are annotation-version differences or undocumented upstream filtering. The source table also reused one gene alias for two distinct identifiers, which must be disambiguated before plotting.

\end{enumerate}
